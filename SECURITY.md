# Security policy

Bloem Admin is [offered without support](README.md). Security vulnerabilities are the one exception to
the rule that reports are not answered: they may be reported, privately.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting. Open the **Security** tab of
[Bloem-Studios/bloem-admin-apple](https://github.com/Bloem-Studios/bloem-admin-apple) and choose
**Report a vulnerability** (<https://github.com/Bloem-Studios/bloem-admin-apple/security/advisories/new>). Do not open a
public issue or pull request for one.

Include what you found, the app version, the iOS version and the steps to reproduce it. Do not include real server
addresses, tokens or passwords.

No response, fix or timeline is promised.

## What is in scope

- The app: how it stores sign-in tokens, the app lock, deep links, widgets, notifications and network handling.
- The release process: signing and the integrity of the builds the maintainers publish.

Problems in a Silo or Bloem server belong to that server's own project. Problems in a third-party component belong to its
maintainers.

## Supported versions

Only the latest release is considered.
